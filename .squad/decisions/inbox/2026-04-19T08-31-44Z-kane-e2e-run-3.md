# Decision: E2E Run 3 — npm Audit Level + next.js Upgrade

**Date:** 2026-04-19  
**Author:** Kane (Tester)  
**Context:** PR #190 feature/openclaw-integration — E2E run analysis post cde6b79a + 0ab4aac6

---

## Decision: Upgrade next.js to ^16.2.4 to unblock CI

After the submission redirect skip guards (0ab4aac6) were merged, the CI "Frontend Quality"
job started failing on a newly-published HIGH severity advisory for next.js
(GHSA-q4gf-8mx6-v5v3: DoS with Server Components, affected range 16.0.0-beta.0 – 16.2.2).

This blocked the entire Preview Deployment pipeline → E2E tests were never scheduled
(result: skipped). The fix was to bump `"next": "^16.1.1"` → `"^16.2.4"` in package.json.

**Rationale:** The vulnerability is HIGH severity and was newly published between April 7 and
April 19, explaining why CI passed previously. next.js 16.2.4 is a non-breaking minor update.

---

## Implication for Team

The CI npm audit check fails on HIGH+ severity vulnerabilities only (the 7 moderate vulns from
hono/dompurify/langsmith did not block CI previously). Team should note:

1. **npm advisory databases are live** — a passing CI can start failing on unchanged code
   if a new CVE is published for a dependency. This is not a regression in the code itself.

2. **E2E test result "skipped" ≠ E2E tests ran and skipped** — when E2E shows 0 results,
   check "Wait for CI" and "Frontend Quality" jobs first. The E2E job never starts if CI fails.

3. **Backend noload fixes are now comprehensive** (59dc0c58 + a2d8974c + d6d4e4c4):
   - list endpoint (_build_video_query) ← eebb47b5
   - detail endpoint (get_video_detail) ← d6d4e4c4
   - video_service.py submit/get/reprocess ← 59dc0c58
   - library_service.py create/list ← a2d8974c

   All four layers are now guarded. The next E2E run should see the submission tests
   PASS (not skip) if migration 015 has been applied in the preview DB.
